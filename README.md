# VVSPEC2026_project

> **Проект ВВС**  
> **Тема:** Автоматизированная система обнаружения нецелевого поведения складских колёсных роботов

---

## 🎯 Цель проекта
Разработать программный комплекс для автоматизированного мониторинга телеметрии с малой задержкой и выявления аномалий в движении складских колёсных роботов, позволяющий оперативно обнаруживать сбои навигации, вовремя направлять сотрудника на ремонт и сокращать время простоя техники.

---

## ⚙️ Задача системы
По телеметрии, поступающей с множества роботов в реальном времени, система выявляет **нецелевое поведение**. 

* **Текущий паттерн аномалии:** повторяющиеся циклические движения в окрестности одной точки (возникает при ошибках навигационной системы — например, когда робот застрял в локальном минимуме `costmap` или столкнулся с препятствием, которое не способны зафиксировать его датчики, напр. лидар и зеркало).
* **Сценарий реагирования:**
  1. Система фиксирует нецелевое поведение и отправляет сигнал на веб-панель оператора.
  2. Оператор вызывает ремонтную бригаду для оперативного устранения проблемы.
  3. После восстановления работы оператор отмечает в веб-интерфейсе, что ошибка исправлена.

## 🏗️ Архитектура и реализация

Система построена на базе **микросервисной архитектуры**, что позволяет дорабатывать, обновлять и масштабировать отдельные компоненты независимо друг от друга с минимальным влиянием на остальную систему.

### 1. Симуляция и сбор телеметрии (`ROS2 + gRPC-клиент`)
* **Симулятор:** в качестве модели робота используется лёгкий двумерный (2D) симулятор, нетребовательный к ресурсам и подходящий для быстрого тестирования.
* **Универсальная ROS2-нода:** подписывается на топики, указанные в файле конфигурации `config.json`, и отправляет телеметрию на сервер по протоколу **gRPC**. Благодаря конфигурируемости нода совместима с любыми роботами на базе ROS2, публикующими данные о траектории движения.

### 2. Бэкенд и хранение данных (`FastAPI + gRPC-сервер + PostgreSQL`)
* **Приём и обработка:** связка из **gRPC-сервера** (для высокопроизводительного приёма потока телеметрии) и **FastAPI-сервера** (директория `backend_ml`), отвечающего за взаимодействие с БД и обслуживание запросов веб-клиентов.
* **База данных (PostgreSQL):** состоит из трёх основных таблиц:
  1. `anomalies` — учёт зафиксированных аномалий и статусов их исправления.
  2. `robots` — реестр подключённых роботов и их текущее состояние (`online` / `offline`).
  3. `telemetry` — журнал поступающей телеметрии.

### 3. Модуль ML-аналитики (`ML-worker`)
* Расположен в директории `ML`.
* С заданной периодичностью (`POLL_INTERVAL_S`) запрашивает у бэкенда срез телеметрии за скользящее временное окно (`ANALYSIS_WINDOW_S`).
* Вычисляет поведенческие признаки движения с помощью `anomaly_detector/compute_behavioral_indicators`.
* Передаёт признаки в классификатор, который оценивает вероятность наличия нецелевого поведения в конкретный момент времени.

### 4. Веб-панель оператора (`Frontend`)
* Отображает список активных роботов, ключевые метрики их работы и ленту обнаруженных аномалий.
* Предоставляет оператору интерфейс для подтверждения устранения сбоя после работы ремонтников.
